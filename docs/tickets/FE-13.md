# FE-13 — Month-end exports & receipt archive (`/admin/reports`)

**Area:** Reporting and audits
**Depends on:** REPORT-01, AUDIT-ARCHIVE-01, FILE-01, AUDIT-LOG-01, DB-01, FE-03
**Blocks:** None; this is the last admin screen in the MVP sequence.

## Context

Each month the office prepares one participant's expenses for Patty to enter into the
Ministry portal manually. The app's job is to produce a copy/paste-ready workbook in the
Ministry's template and to retrieve historical receipts when an audit or a question comes
up. It does not submit anything to PassportONE (decisions.md 4).

The stub has the right four panels — export form, submission tracker, archive filters, and
an audit file table — with no data or files behind them.

## Current stub

`src/app/admin/reports/page.tsx` — monthly export form, tracker table, audit receipt archive
form, and audit files table.

## Deliverables

1. **Monthly export** — participant, fiscal year, and month; generate through REPORT-01
   using the current Ministry spreadsheet template. Show the prepared row count and the
   template version before download. The file downloads from the API; the browser never
   assembles a workbook.
2. **Export result** — filename that names participant, year, and month; a warning when
   the participant has expenses in the month that are not `confirmed`, so the export is not
   mistaken for final; and a link to re-download the last generated file while it exists.
3. **Submission tracker** — per participant and period: expense count, receipt count, local
   export status (`draft`, `ready_for_review`, `exported`), and a **manually entered** portal
   status. Never infer or claim portal status.
4. **Receipt archive** — participant, date range, optional category and amount filter;
   request a server-built archive and download the stream. Show progress for large ranges
   and allow cancel.
5. **Audit files table** — period, participant, receipt count, created at, created by, and
   download. Only archives this deployment generated; no fabricated rows.
6. **Audit events** — generating an export or archive writes an `audit_events` row with
   actor, parameters, and result. Failed generations are recorded too.
7. **States** — no expenses in the period, template missing or outdated, generation failed
   partway, archive too large for the requested range (with a suggested narrower range),
   download link expired.
8. **Accessibility** — downloads are real links or buttons with discernible names; progress
   is announced; the tables are navigable without a mouse.

## Data

Confirm in REPORT-01 / AUDIT-ARCHIVE-01:

- `GET /api/v1/reports/monthly-export?participant_id=&fiscal_year=&month=` → file stream or
  a generated-export record with a download URL.
- `GET /api/v1/reports/receipt-archive?participant_id=&from=&to=&category_id=`
- `GET /api/v1/exports?participant_id=&cursor=`
- `GET /api/v1/audit-events?entity_type=export&cursor=`

## Out of scope

- Submitting to PassportONE or any Ministry API.
- Editing the Ministry template in code; the template is supplied and versioned outside
  this repository.
- Long-term retention policy; the archive format and cadence need a recorded decision.

## Acceptance criteria

- Generating an export for a synthetic participant and month yields a workbook whose
  columns match the supplied template, and the row count matches the confirmed expenses in
  that period.
- The screen warns, without blocking, when unconfirmed expenses exist in the period.
- Portal status is only ever what a staff member entered; nothing in the UI derives it.
- An archive download contains exactly the receipts in the requested range and is named
  predictably.
- Generating either artifact creates one audit event, including a failed attempt.
- No real receipt or participant data is used to build or test the export.

## Verification

`npm run lint`, `npm run typecheck`, `npm run build`. Manual against a local API with
synthetic data: empty month, mixed statuses, archive with zero results, oversized range,
expired download, and the audit rows after each. Open the generated workbook in a
spreadsheet application and compare against the template.
