# FE-05 — Add an expense (`/worker/submit`)

**Area:** Worker portal
**Depends on:** API-02 (expense ledger), FILE-01 (receipt upload), BE-01 (coverage), OCR-01 /
OCR-02 (advisory extraction), DB-01, FE-03, FE-04
**Blocks:** FE-11 (review queue needs submitted receipts)

## Context

The research flow starts with a participant, then the receipt, then the expense details and
category, then a coverage check. PassportONE shows an Expense Log with an Add Expense
action and a separate Log Expense form; this screen should mirror that sequence without
submitting anything to the Ministry.

Today every field is disabled and the draft table is empty. The category reference list is
real transcription from the supplied PDF and can stay as read-only reference.

## Current stub

`src/app/worker/submit/page.tsx` — three numbered sections (upload, details, category
reference) and a draft expense table.

## Deliverables

1. **Step 1 — participant and receipt** — participant comes from open assignments and
   carries over from FE-04 when present. File input accepts PDF, JPEG, and Word, showing
   the size limit the server reports; do not hardcode a limit FILE-01 has not confirmed.
   Drag-and-drop is optional; the file picker must work on mobile.
2. **Upload behavior** — post to FILE-01's signed-upload flow, show progress, allow retry,
   and never keep the file in client state after a successful upload. Multiple files are
   one receipt object each (DB-01); a multi-page document is a single receipt.
3. **Step 2 — expense details** — date, vendor/description, total amount, category,
   subcategory (only when the category has them), "other category detail" required when
   "Other types, please specify" is chosen, and a worker note. Amount input is text with
   decimal parsing to a string, two decimals; reject letters and more than two decimals
   before sending.
4. **Coverage preview** — call BE-01; display covered and out-of-pocket and the assumptions
   used. This is a preview: adding the expense must not create a ledger entry as a side
   effect of calculating.
5. **Draft batch** — rows added locally are visibly drafts and removable. Saving submits
   the batch to API-02; partially failed batches report which rows failed and keep the rest.
6. **Existing submissions** — the table lists the worker's own expenses for the selected
   participant and year, read-only for rows from other sources
   (`source_kind = day_program_invoice`, `import`). Editing a confirmed expense is not
   offered: DB-01 voids and re-enters.
7. **Missing receipt** — `expenses.receipt_id` is nullable in the schema. Do not add a
   client-only requirement; allow saving without a receipt and surface it as a review
   follow-up, unless AUTH/API policy later makes it mandatory.
8. **States** — upload failed, OCR skipped or failed (advisory only, never blocks entry),
   duplicate submit prevention, server validation errors mapped back to fields.

## Data

- `POST /api/v1/receipts` → signed upload target (FILE-01).
- `POST /api/v1/expenses` → batch or single create (API-02); `fiscal_year` never sent.
- `GET /api/v1/participants/{id}/expenses?fiscal_year=` for the submission list.
- `POST /api/v1/coverage` (BE-01) — proposed; confirm the path in API-01.

## Out of scope

- OCR accuracy work and extraction UI: OCR-01 / OCR-02.
- Admin review and correction: FE-11.
- Ministry submission, invoice generation, payment.
- Mileage or meal rules on an expense.

## Acceptance criteria

- A worker can upload a synthetic PDF receipt, add one expense with category and amount,
  and see it in their own list with the correct coverage split.
- Covered + out-of-pocket equals total, and the server rejects a mismatch; the UI shows the
  server's error on the amount field rather than a generic banner.
- Selecting "Other types, please specify" requires non-blank detail; clearing the detail
  blocks submit.
- A subcategory control appears only for categories that have subcategories and is required
  when the category defines them.
- Reprinting the file input after upload shows no file; the receipt is referenced by id.
- Rows from other sources render read-only.
- A failed upload leaves the rest of the form intact and can be retried.

## Verification

`npm run lint`, `npm run typecheck`, `npm run build`. Manual with synthetic PDFs and a local
API: happy path, missing receipt, invalid amount, upload failure, OCR failure. Check the
form at 375px with the keyboard open. No real receipts, ever.
